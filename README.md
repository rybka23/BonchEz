# Bonch TG Bot — авто-отметка на парах через lk.sut.ru

Telegram-бот, который логинится в личный кабинет [lk.sut.ru](https://lk.sut.ru)
(СПбГУТ им. Бонч-Бруевича) и умеет жать кнопку «Отметиться» — по команде
или автоматически по расписанию.

## Структура проекта

```
bonch_tg_bot/
├── app/
│   ├── __init__.py
│   ├── main.py              # точка входа — asyncio + bot.start_polling()
│   ├── bot.py               # создание Bot и Dispatcher
│   ├── config.py            # читает .env
│   ├── states.py            # FSM-состояния (LoginStates)
│   ├── middlewares.py       # AccessMiddleware — белый список
│   ├── sessions.py          # кэш BonchClient + переавторизация
│   ├── runtime.py           # общее состояние: store, sessions, auto_enabled
│   ├── scheduler.py         # APScheduler + auto_checkin_job
│   ├── handlers/
│   │   ├── __init__.py      # register_handlers(dp)
│   │   ├── start.py         # /start, /help
│   │   ├── auth.py          # /login (FSM), /logout
│   │   ├── checkin.py       # /checkin, /auto on|off
│   │   └── info.py          # /status, /schedule
│   └── services/
│       ├── __init__.py
│       ├── bonch_client.py  # HTTP-клиент ЛК
│       └── storage.py       # SQLite + Fernet-шифрование паролей
├── data/                    # SQLite-база (создаётся автоматически, в .gitignore)
├── requirements.txt
├── .env.example
├── .gitignore
└── README.md
```

## Эндпоинты ЛК, которые использует бот

Имена полей и пути восстановлены из JS-файлов сохранённой страницы кабинета:

| Что делает бот              | Метод | URL                                                              | Тело                                             |
|-----------------------------|-------|------------------------------------------------------------------|--------------------------------------------------|
| Логин                       | POST  | `/cabinet/lib/autentificationok.php`                             | `users=<логин>&parole=<пароль>`                  |
| Запись истории навигации    | POST  | `/cabinet/project/cabinet/history.php`                          | `subconto=menu&key=<key>`                        |
| Загрузка «Занятия журнала» | POST  | `/cabinet/project/cabinet/modul/raspisanie/zanatie_jurnal.php`  | `subconto=menu&key=6112`                         |
| Расписание на сегодня       | POST  | `/cabinet/project/cabinet/forms/raspisanie.php`                  | `subconto=menu&key=6118`                         |

Логин возвращает числовой ID пользователя (>0) при успехе или `0` / pipe-разделённую
строку с описанием ошибки при неудаче. Сессия хранится в cookie `PHPSESSID`.

## Установка

### 1. Установи зависимости

```bash
cd bonch_tg_bot
python -m venv .venv
source .venv/bin/activate         # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Создай бота в Telegram

- Открой [@BotFather](https://t.me/BotFather)
- `/newbot` → придумай имя и username
- Скопируй токен

### 3. Подготовь конфиг

```bash
cp .env.example .env
```

Открой `.env` и заполни:

```dotenv
BOT_TOKEN=1234567890:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
ALLOWED_USER_IDS=123456789
```

Сгенерируй ключ шифрования паролей и подставь его в `FERNET_KEY`:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

### 4. Узнай свой Telegram ID

Напиши [@userinfobot](https://t.me/userinfobot) — он пришлёт твой ID.
Добавь его в `ALLOWED_USER_IDS` (через запятую, можно несколько).

### 5. Запусти бота

```bash
python -m app.main
```

В Telegram открой бота и нажми `/start`.

## Команды

| Команда       | Что делает                                                |
|---------------|-----------------------------------------------------------|
| `/start`      | приветствие                                              |
| `/help`       | то же, что /start                                         |
| `/login`      | ввод логина и пароля от ЛК (пароль удаляется из чата)    |
| `/checkin`    | отметиться прямо сейчас                                   |
| `/status`     | проверить, жива ли сессия                                 |
| `/schedule`   | расписание на сегодня                                      |
| `/auto on`    | включить авто-отметку каждые N минут (из `.env`)          |
| `/auto off`   | выключить авто-отметку                                    |
| `/logout`     | забыть мои данные                                          |

## Как работает отметка на lk.sut.ru

Флоу полностью восстановлен из JS-функций `update_zan()`, `open_zan()` и `close_zan()` в HTML расписания. Это **двухшаговый процесс**:

### Полный флоу

| Шаг | JS-функция | POST | Что возвращает сервер |
|-----|------------|------|------------------------|
| 0 | (загрузка) | `subconto=menu&key=6118` | HTML с таблицей занятий, в каждой строке `<span id="knopXXX"><a onclick="update_zan(XXX);">...</a></span>` |
| 1 | `update_zan(ID)` | `open=3&rasp=ID` | JSON `{"data": "<HTML>"}` — кнопка-индикатор |
| 2 | `open_zan(ID, WEEK)` | `open=1&rasp=ID&week=WEEK` | JSON `{"data": "<HTML>", "id": "<журнал_id>"}` — отметка |
| 3 (опц.) | `close_zan(JID, ID)` | `open=2&rasp=JID` | завершение занятия |

### Состояния кнопки на шаге 1

Сервер в `JSON.data` возвращает один из вариантов:

| HTML в `data` | Что значит | Действие бота |
|--------------|------------|---------------|
| `Кнопка появится в 12:50. Обновить.` | Пара ещё не началась (кнопка появится за 10 мин до начала) | Пробует следующее занятие |
| `<a onclick="open_zan(1118024,7);">Начать занятие</a>` | Можно отметиться | **Делает шаг 2: POST `open=1&rasp=1118024&week=7`** |
| `<a onclick="close_zan('56649','1118024');">Закончить занятие</a>` | Уже отметили ранее | Сразу возвращает «✅ Успех» |

### Что делает бот

| Команда | Что делает |
|---------|------------|
| `/checkin` | Грузит расписание → для каждого занятия вызывает `update_zan(ID)` → если в ответе есть `open_zan(ID, WEEK)` — вызывает `open_zan(ID, WEEK)` (это и есть отметка). Отмечается на первой доступной паре. |
| `/lessons` | Показывает все занятия на сегодня с их ID, временем, преподавателем, аудиторией, номером недели |
| `/schedule` | Просто показывает расписание как текст |
| `/auto on` | Запускает планировщик — каждые N минут пытается `/checkin`, при успехе выключается |

### Определение номера недели

В JS-вызовах `open_zan(ID, WEEK)` — это номер недели из пагинации расписания (вверху страницы «5 6 **7** 8 9», активная подсвечена). Бот парсит его прямо из HTML:

```python
m = re.search(r'class="page-link[^"]*bg-info[^"]*"[^>]*onclick="showweek\((\d+)\)"', html)
```

Этот же `week` передаётся в `open_zan()` — это критично, без него сервер вернёт ошибку.

## Архитектура

```
                    ┌─────────────────┐
                    │  app/main.py    │  точка входа
                    └────────┬────────┘
                             │
              ┌──────────────┴───────────────┐
              ▼                              ▼
     ┌────────────────┐            ┌──────────────────┐
     │  app/bot.py    │            │  app/scheduler.py │
     │ Bot + Dispatcher│           │  APScheduler     │
     └────────┬───────┘            └────────┬─────────┘
              │                             │
              ▼                             │
     ┌────────────────┐                     │
     │ app/handlers/* │  4 роутера          │
     └────────┬───────┘                     │
              │                             │
              └────────────┬────────────────┘
                           ▼
                  ┌─────────────────┐
                  │  app/runtime.py │  общее состояние:
                  │                 │  store, sessions, auto_enabled
                  └────────┬────────┘
                           │
              ┌────────────┴───────────────┐
              ▼                            ▼
     ┌──────────────────┐       ┌──────────────────┐
     │ app/services/    │       │  app/sessions.py │  переавторизация
     │  bonch_client.py │       │  get_or_restore_ │
     │  storage.py      │       │   client()       │
     └──────────────────┘       └──────────────────┘
```

- **handlers/** — роутеры aiogram, разбитые по группам команд. Каждый в своём файле.
- **services/** — чистая бизнес-логика (HTTP-клиент, БД), без зависимости от aiogram.
- **runtime.py** — разделяемое состояние (store, sessions, auto_enabled).
  Хранится в одном месте, импортируется всеми, у кого нет циклов.
- **middlewares.py** — `AccessMiddleware` режет доступ не из белого списка.
- **scheduler.py** — отдельный модуль с APScheduler-задачей.
- **bot.py** — только сборка `Bot` и `Dispatcher`, без логики.

## Безопасность

- Пароль шифруется Fernet-ключом и хранится в `data/bonch_bot.db`.
- Пароль, который ты вводишь в чат, **удаляется сразу** после обработки.
- Список `ALLOWED_USER_IDS` ограничивает, кто может пользоваться ботом.
- **Не коммить `.env` и `data/` в публичные репозитории.** В `.gitignore` они уже добавлены.

## Если что-то не работает

### Логин не удаётся

- Проверь, что в `users` ты указываешь то, что вводишь в форму ЛК
  (на скриншотах видно, что это **email** типа `mrspedarman@gmail.com`, а не номер студака).
- Запусти тестовый логин в браузере: открой DevTools (F12) → вкладка Network →
  войди в ЛК → найди POST к `autentificationok.php` → сравни Payload с тем,
  что отправляет бот. Поля должны быть `users` и `parole` — это уже подтверждено.

### Кнопка не нажимается / «Кнопка появится в HH:MM»

Это **нормально** — если сейчас не время пары, в ЛК на месте кнопки написано
«Кнопка появится в 12:50. Обновить.». Бот в этом случае ответит:
«Пара ... ещё не началась. Сервер: Кнопка появится в 12:50. Обновить.»

Дождись времени, указанного сервером (или за 10 минут до начала пары), и попробуй снова.
Если и во время пары бот говорит «ещё не началась» — открой ЛК, нажми «Обновить» вручную,
посмотри в Network какой POST уходит, и сравни с тем, что шлёт бот (лог `Отметка через POST`).

### Бот пишет «непонятный ответ» или «найдена кнопка с onclick»

Если в `mes.data` пришёл HTML, который бот не распознал — это значит:
1. ЛК обновился и текст кнопок изменился. Открой `app/services/bonch_client.py`,
   найди `_MARK_DONE_PATTERNS` и `_MARK_NOT_YET_PATTERNS`, допиши туда новые слова.
2. Сервер вернул что-то совершенно другое. Включи debug-логирование:
   ```bash
   sudo journalctl -u bonch-bot -f | grep -i "raw_json\|update_zan"
   ```
   И посмотри, что именно вернул сервер в JSON.data.

### Сессия постоянно отваливается

Это нормально — `PHPSESSID` на Бонче живёт ограниченное время. Бот при каждом
`/checkin` или авто-проверке сначала проверяет `is_logged_in()`, и если
сессия мёртвая — логинится заново по сохранённому паролю.
